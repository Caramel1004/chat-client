# Realtime Chat Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans; use tests and independent review for the transport change.

**Goal:** DB 없이 같은 방의 여러 브라우저가 메시지를 주고받게 한다.

**Architecture:** Supabase Realtime 클라이언트 Broadcast + 정적 Vercel 프론트엔드. 방 메타데이터는 초대 URL, 메시지는 React 메모리에 둔다.

**Tech Stack:** React 19, TypeScript, Tailwind 4, Bun, Supabase Realtime.

**Spec:** `docs/superpowers/specs/2026-10-02-realtime-design.md`

## Global Constraints

- DB/대화 기록 저장/브라우저 비밀 키 금지. 공개 Publishable key만 사용한다.
- 한글 IME, Shift+Enter, 방 생성 모달의 기존 동작 보존.
- 방 이름 40자, 설명 120자, 메시지 2,000자.

## Review Focus

- 전송 실패/연결 단절 시 입력 소실, 중복 전송.
- StrictMode 및 빠른 방 이동 뒤 구독/메시지 유출.
- 잘못된 초대 URL 및 외부 payload.
- 구독 전·소켓 단절 시 SDK의 HTTP fallback 방지.
- 설정 없는 개발/미리보기에서 전송 성공으로 오인.
