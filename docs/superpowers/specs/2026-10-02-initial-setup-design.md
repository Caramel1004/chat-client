# 채팅 클라이언트 초기 설정과 두 페이지

## 목적과 범위
React 19, TypeScript, Tailwind CSS 4 프론트엔드를 만들고 Vercel에 배포한다. 사용자 추가 요청에 따라 패키지 매니저는 Bun, 화면은 채팅 목록과 채팅방 두 페이지로 구성한다.

## 구성과 흐름
- Vite 정적 SPA, TypeScript strict, ESLint, React Router를 사용한다.
- `/`는 채팅 목록이며 미리보기용 라운지 한 개를 표시한다.
- `/rooms/lounge`는 채팅방이다. 없는 방은 목록으로 돌아가는 안내를 표시한다.
- 목록 상단 버튼으로 채팅방 생성 모달을 연다. 방 이름은 필수(최대 40자), 설명은 선택(최대 120자)이다. 공백 이름은 생성할 수 없다. 만들기 후 목록에 추가하며 취소·닫기·Esc는 생성 없이 닫는다. 다시 열면 입력을 초기화한다.
- 방 목록을 앱 메모리 상태로 관리한다. 생성한 방은 고유 ID를 사용해 입장할 수 있고 메시지는 방별로 분리한다. 생성한 방도 새로고침 시 사라진다.
- Enter와 전송 버튼으로 본인 메시지를 보드에 추가한다. 공백은 거부하고 Shift+Enter는 줄바꿈한다. 한글 IME 조합 Enter는 전송하지 않는다. 입력은 최대 2,000자다.
- React 메모리 상태를 사용한다. 페이지 이동 중에는 유지되고 새로고침 시 소멸한다.
- 다른 사용자와 연결되지 않은 로컬 미리보기임을 두 화면에서 명확히 알린다. 가짜 사용자나 메시지, 온라인 수는 표시하지 않는다.
- Tailwind CSS 4 Vite 플러그인, Bun 1.4.2와 bun.lock, Node 22.13 이상인 22.x를 사용한다.

## 배포
Vercel Vite 프리셋에서 bun run build 결과인 dist를 배포한다. SPA rewrite로 방 주소 직접 접속과 새로고침을 지원한다. 기본 vercel.app 주소를 사용하며 인증 정보는 커밋하지 않는다.

## 검증
전송, 공백 차단, IME, 줄바꿈, 페이지 이동 후 메시지 유지, 잘못된 방 접근을 Vitest로 확인한다. lint, 타입 검사, 프로덕션 빌드, 데스크톱/모바일 UI, Vercel 배포 후 직접 방 URL을 확인한다.

## 후속 단계
WebSocket 중계 서비스 연결과 다중 사용자 통신은 이후 구현한다. 영구 메시지 저장과 계정은 이번 범위에 포함하지 않는다.
