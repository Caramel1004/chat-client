# DB 없는 실시간 채팅

2026-10-03: 사용자 요청에 따라 Supabase Realtime으로 전환한 최종 설계.

- 목적: 같은 방에 접속한 A와 B가 Enter로 보낸 메시지를 즉시 주고받는다.
- React 19, TypeScript, Tailwind 4, Bun을 유지한다. Vercel에 정적 프론트엔드를 배포한다.
- Supabase Realtime 클라이언트 Broadcast로 WebSocket 메시지를 중계한다. `private: false`, `self: true`, `ack: true`를 사용한다.
- 환경 변수는 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`이다. 브라우저 공개용 `sb_publishable_...` 키만 사용한다. 별도 토큰 발급 함수는 없다.
- Supabase 프로젝트는 필요하지만 채팅 DB 테이블, SQL, Postgres Changes, Database Broadcast, Auth는 사용하지 않는다.
- 메시지와 방 목록은 브라우저 메모리에만 둔다. 최근 500개 메시지로 제한하며 기록 조회/저장 API나 localStorage를 사용하지 않는다. 제공자 내부 운영 로그/전송 버퍼의 부재까지 보장하지 않는다.
- 기본 라운지는 누구나 입장한다. 사용자 생성 방은 이름·설명이 포함된 초대 URL로 직접 입장/새로고침할 수 있다. 새로운 브라우저의 홈페이지에는 전체 사용자 생성 방을 자동으로 나열하지 않는다.
- 현재 방만 구독한다. 내 메시지/상대 메시지를 구분하고 메시지 ID로 중복을 제거한다. 수신 데이터의 방 ID, 텍스트, 발신자, 시간을 검증한다.
- 미설정/연결 중/연결됨/재연결 중/오류 상태를 표시한다. 구독과 실제 소켓 연결이 준비되기 전 전송을 막아 HTTP fallback을 방지한다.
- 서비스가 전송을 확인한 뒤 입력을 지우고 실패·시간 초과 시 초안을 보존한다. 서비스 수락은 모든 상대방 수신 보증이 아니다.
- 방을 떠나거나 StrictMode가 재실행될 때 기존 연결을 정리한다. 새 접속/새로고침에서 과거 기록을 불러오지 않는다. 연결 중단 동안의 메시지는 재생하지 않는다.
- 로그인 없는 공개 베타다. 초대 링크나 게스트 이름은 접근 제어나 검증된 신원이 아니다.

실제 프로젝트 연결 설정과 Vercel 인증이 없으면 운영 연결과 배포는 검증할 수 없다. 로컬 검증과 실서비스 검증 결과를 구분한다.
